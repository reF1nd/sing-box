# eBPF inbound kernel requirements

This page is the deployment checklist for the eBPF inbound. The [configuration
reference](/configuration/inbound/ebpf/) documents configuration semantics, and
the [troubleshooting guide](/manual/misc/ebpf-troubleshooting/) documents issue
reports and diagnostics.

## Capability levels

sing-box probes the capabilities it uses at startup. A vendor kernel may
backport a feature without matching its upstream version, so the probe result
is authoritative.

| Capability | eBPF inbound feature | Level |
|------------|----------------------|-------|
| `CONFIG_BPF_SYSCALL` | BPF maps, program loading, helper calls, and links | Required for every mode |
| `CONFIG_CGROUPS` and `CONFIG_CGROUP_BPF` | Local cgroup v2 socket-address interception | Required for `local` and `hybrid` |
| `CONFIG_INET` | IPv4 TCP/UDP and the IPv4 BPF helpers | Required for TCP/UDP |
| `CONFIG_IPV6` | Native IPv6 interception and IPv6 packet parsing | Required when native IPv6 is enabled |
| `CONFIG_NET_SCHED`, `CONFIG_NET_CLS_ACT`, `CONFIG_NET_CLS_BPF`, `CONFIG_NET_SCH_INGRESS` | TC ingress/egress classifiers and the clsact fallback | Required for `shared` and `hybrid` |
| `CONFIG_BPF_JIT` and architecture `CONFIG_HAVE_EBPF_JIT` | Native execution of BPF programs | Performance optimization |

`CONFIG_BPF` is selected by `CONFIG_NET`, and the following symbols are
normally selected automatically: `CONFIG_SOCK_CGROUP_DATA`,
`CONFIG_NET_XGRESS`, `CONFIG_NET_INGRESS`, `CONFIG_NET_EGRESS`, and
`CONFIG_NET_CLS`. They should be visible as enabled in `/proc/config.gz` on a
built-in configuration.

The Hash, Array, LRUHash, LPMTrie, and PerCPUArray map types used by this inbound
do not have separate user-selectable Kconfig switches; they are provided by
`CONFIG_BPF_SYSCALL`. The same applies to the map and packet helpers reported
by `tools ebpf status`.

`CONFIG_BPF_STREAM_PARSER` is not used. It enables SK_SKB stream parser and
verdict attachment for SOCKMAP/SOCKHASH, but the eBPF inbound no longer has a
TCP splice path. A failure for that feature in a report generated by an older
build affects only the removed experimental optimization, not current local or
shared interception. `CONFIG_BPF_LSM`, `CONFIG_BPF_EVENTS`,
`CONFIG_BPF_KPROBE_OVERRIDE`, `CONFIG_DEBUG_INFO_BTF`, and CO-RE are also not
required.

## Recommended configuration fragments

For local TCP/UDP plus shared mode, use at least:

```text
CONFIG_NET=y
CONFIG_INET=y
CONFIG_IPV6=y
CONFIG_BPF=y
CONFIG_BPF_SYSCALL=y
CONFIG_CGROUPS=y
CONFIG_CGROUP_BPF=y
CONFIG_NET_SCHED=y
CONFIG_NET_CLS_ACT=y
CONFIG_NET_CLS_BPF=y
CONFIG_NET_SCH_INGRESS=y
CONFIG_BPF_JIT=y
```

Optional diagnostic visibility for `/proc/config.gz` requires:

```text
CONFIG_IKCONFIG=y
CONFIG_IKCONFIG_PROC=y
```

These two symbols do not enable any runtime eBPF capability.

`CONFIG_NET_CLS_BPF` and `CONFIG_NET_SCH_INGRESS` may be modules on a normal
Linux distribution, but the modules must be installed and loaded before
shared mode attaches its TC filters. Built-in (`y`) is the least surprising
choice for an Android or firmware kernel.

## Version and runtime prerequisites

- Linux 4.19 is the compatibility baseline for shared mode and TCP-only local
  mode.
- Local UDP needs the upstream Linux 5.2 cgroup UDP4/UDP6 `recvmsg` hooks, or a
  vendor backport. A newer version number alone does not prove that the hooks
  are enabled.
- Local mode needs a mounted cgroup v2 filesystem and a writable path below
  that mount. sing-box does not mount or create the cgroup hierarchy for you.
- The process needs root or equivalent BPF, system-administration, and
  network-administration privileges. On newer kernels this commonly means
  `CAP_BPF`, `CAP_SYS_ADMIN` where required by the vendor kernel, and
  `CAP_NET_ADMIN`.
- Shared mode needs a real Ethernet-like downstream interface, TC support, and
  writable `/proc/sys/net/ipv4/conf/<interface>/route_localnet`. It does not
  provide forwarding, NAT, DHCP, hotspot service, or IPv6 router advertisements.
- `CONFIG_DEBUG_INFO_BTF`, CO-RE, `CONFIG_BPF_LSM`, tracing, kprobes, and
  `bpffs` pinning are not required by this inbound.
- Shared ingress bypasses real IPv4 fragments and non-atomic IPv6 fragments.
  Shared egress drops such fragments when their source is an internal token
  address so the address cannot escape onto the downstream network. IPv6
  atomic fragments are parsed normally; no fragment-tracking kernel feature is
  required.

Check the effective kernel configuration with:

```sh
zcat /proc/config.gz | grep -E \
'CONFIG_(NET|INET|IPV6|BPF|CGROUP|NET_SCHED|NET_CLS|NET_SCH|NET_XGRESS|SOCK_CGROUP_DATA)'
```

`/proc/config.gz` is only available when the kernel exposes IKCONFIG through
both `CONFIG_IKCONFIG` and `CONFIG_IKCONFIG_PROC`; those diagnostic options are
separate from eBPF support.

## Linux packages

On a standard Linux distribution, the sing-box binary does not need a system
libbpf or a cilium package. The eBPF objects are shipped with the binary, and
the runtime is pure Go when built with `with_ebpf`.

Install `iproute2` for the `ip` and `tc` commands used to inspect interfaces,
qdiscs, filters, routes, and policy rules. Install `bpftool` only when you need
low-level inspection or profiling; it is not a sing-box runtime dependency.
Distribution package names may split these into `iproute2`, `iproute2-tc`, or
`linux-tools-common`/`linux-tools-<version>`.

## OpenWrt packages

For shared mode, install the kernel module packages matching the running
OpenWrt kernel:

```sh
opkg update
opkg install kmod-sched-core kmod-sched-bpf ip-full tc-bpf
```

`kmod-sched-core` supplies the scheduler/clsact pieces, while
`kmod-sched-bpf` supplies the BPF TC classifier. `ip-full` provides the full
`ip` tooling and `tc-bpf` provides a `tc` binary with BPF support for setup and
diagnostics; neither is linked into sing-box.
Some OpenWrt releases build these modules into the kernel or use slightly
different package splits, so verify with `opkg list` and `lsmod`. Load modules
when they are packaged as modules:

```sh
modprobe sch_ingress
modprobe cls_bpf
```

OpenWrt still needs the kernel configuration and cgroup v2 mount described
above. A package install cannot add a missing `CONFIG_CGROUP_BPF`, TC support,
or other built-out kernel capability; those require a custom kernel build.
Some images provide `cgroupfs-mount` as a convenience package for mounting the
cgroup v2 hierarchy; it is optional if the hierarchy is already mounted by the
init system.

## Verification

Run the probe matching the configured path:

```sh
sing-box tools ebpf status --mode local --network tcp,udp --json
sing-box tools ebpf status --mode shared-network --interface br-lan --json
```

`FAIL` under `required` means the selected path cannot provide its normal
correctness guarantees. `FAIL` under `performance` means that optimization is
unavailable and the documented fallback is used.
